## 1. 🔴 必修

### A. 记忆工具调用会抑制后台总结（判据误用累积段）

**现象**（实测复现）：

```
场景一：模型在第 1 轮调过一次 memory_md_journal，其后每轮都有长内容

  现状                        实际总结覆盖: U2 | U3 | U4    ← 第 1 轮内容永久丢失
  对照（第1轮不调工具）          实际总结覆盖: U1 | U2 | U3 | U4

场景二：模型「勤勉」到每轮都调记忆工具

  现状                        实际总结覆盖: （无任何总结）  ← 该会话完全停写
```

**根因**：两处叠加。

1. `summarize.mjs:747-748` 的 `pending` 是**累积段**（从上次成功总结到现在），不是本轮：

```js
// ★ 取「上次成功总结之后」的全部事件，而不只是本轮 —— 这是跨回合补偿的核心。
const pending = eventsSinceTurn(events, state.doneTurn)
```

2. 但 `summarize.mjs:767` 把这个**累积段**直接喂给了「本轮是否动过记忆」的判据，并顺手推进游标：

```js
if (touchedMemoryThisTurn(pending)) {   // ← 传的是累积段
  state.doneTurn = turn                  // ← 游标被推进，这段再也不会被总结
  return
}
```

于是**只要累积段里曾经出现过一次记忆工具调用，该判据此后恒为真**：每次总结都被跳过，而游标被推进（`:768`）。

这**正是 `summarize.mjs:289-301` 注释亲口警告过的 bug**：

```
⚠️ 为什么必须只取最后一轮：judgement 用的是 `tool/call`，而**累积段**包含
从上次成功总结到现在的所有轮。一旦模型在**任意一轮**调过记忆工具，
那个调用就永远留在累积段里 —— 之后每一轮判据都恒为真，**该会话的后台日志
从此永久停写**。这是实测踩到的真 bug（preset-md 会话第 5 轮调了一次
`memory_md_journal`，第 6、7 轮就再也没写过日志）。
```

**改法**（一行）：判据只看本轮——

```js
// summarize.mjs 约 :767
if (touchedMemoryThisTurn(lastTurnEvents(pending))) {   // ← 加 lastTurnEvents
  state.doneTurn = turn
  return
}
```

`lastTurnEvents` 已经写好了（`:302`，且正是为此而写），只是从未被调用。见 B。

> **为什么不能简单删掉这个判据**：它的**意图是对的**——主模型自己调过记忆工具时，后台不必重复总结。要保留意图、修正输入。

### B. `lastTurnEvents` 是死代码，注释与调用点矛盾

**证据**：

| 位置 | 内容 |
|---|---|
| `summarize.mjs:302` | `function lastTurnEvents(events) { ... }` —— 定义 |
| `summarize.mjs:312` | 注释：*"调用方必须传「本轮事件」（见 `lastTurnEvents`），不能传累积段"* |
| `summarize.mjs:767` | 实际调用 `touchedMemoryThisTurn(pending)` —— **传的是累积段** |
| 全仓 grep | `lastTurnEvents` **零调用**（仅 `:302` 定义与 `:312` 注释提及） |

即：函数写好了、注释也把「必须怎么用」写清了，**但没有任何地方用它**。这是 A 的直接成因。

**改法**：按 A 接上即可，函数本身无需改动。补测试锁住（见下）。

### C. 只读工具也会抑制总结（A 的后果放大）

**现象**（实测）：

```
第 3 轮出现以下工具调用，看是否抑制该轮总结：

  无工具调用（基线）                 总结 3 次 / 3 轮
  memory_md_journal（写日志）        总结 2 次 / 3 轮
  memory_md_save（写记忆）           总结 2 次 / 3 轮
  memory_md_search（只读检索）        总结 2 次 / 3 轮   ← 只读也抑制
  memory_md_read（只读读取）          总结 2 次 / 3 轮   ← 只读也抑制
  read（无关工具，对照）              总结 3 次 / 3 轮
```

**根因**：判据用前缀匹配，把四个工具**一视同仁**（`summarize.mjs:318`）：

```js
if (typeof name === 'string' && name.startsWith('memory_md_')) return true
```

而四个工具里只有两个是**写**操作（`tools.mjs:41-44`）：

```js
export const TOOL_WRITE   = 'memory_md_save'
export const TOOL_SEARCH  = 'memory_md_search'    // 只读
export const TOOL_READ    = 'memory_md_read'      // 只读
export const TOOL_JOURNAL = 'memory_md_journal'
```

**「读过记忆」不等于「本轮的记忆已经处理好了」**——模型可能只是查了一下旧记忆，本轮的结论仍值得沉淀。用 `search` 去抑制总结，逻辑上说不通。

**改法**：只认写操作。

```js
// summarize.mjs:314-321
/** 本轮里模型是否**写过**记忆（只读的 search/read 不算）。 */
function touchedMemoryThisTurn(events) {
  for (const event of events) {
    if (event?.type !== 'tool/call') continue
    const name = event.data?.name
    if (name === TOOL_WRITE || name === TOOL_JOURNAL) return true
  }
  return false
}
```

⚠️ **注意依赖方向**：`summarize.mjs` 目前**没有 import** `TOOL_WRITE`/`TOOL_JOURNAL`（定义在 `tools.mjs:41-44`）。直接 import 有循环依赖风险（`tools.mjs` 已 import `store.mjs`、`context.mjs`）。两个更稳的做法：

- **就地写字符串常量**（`'memory_md_save'` / `'memory_md_journal'`），注释里指明与 `tools.mjs:41,44` 对应；
- 或把这些工具名常量提到一个无依赖的小模块，两边都从那里取。

**建议同时补回归测试**（当前零覆盖）：

```
1) 本轮调过 memory_md_save          → 跳过（判据生效）
2) 累积段里有、但本轮没有            → **不得**跳过（锁 A）
3) 本轮调 memory_md_search / read   → **不得**跳过（锁 C）
```

### E. `max-tokens` 分支零测试覆盖

**证据**：

| 位置 | 内容 |
|---|---|
| `summarize.mjs:397-417` | 为截断事故新增的观测逻辑：`chunk.reason?.kind === 'max-tokens'` → 打 warn「尝试抢救」 |
| `test/summarize.test.mjs:84` | 假 LLM 只 yield `{ type: 'finish', reason: 'stop' }` |
| 全仓 grep `max-tokens` | **0 命中** |

即：**为某个真实事故加的修复，没有回归锁**。同处 `MAX_OUTPUT_TOKENS` 也只断言 `>= 4000`（`summarize.test.mjs:281`），锁不住具体值——而"上限提到 4000"正是那次修复的动作之一。

**改法**：让假 LLM 能产出截断 finish chunk，并断言观测路径被触发：

```js
yield { type: 'finish', reason: { kind: 'max-tokens' } }
// 断言 logger.warn 收到了含 max-tokens 的消息
```

> **同类风险提示**：只加观测代码不加测试 = 下次没人知道它还在不在工作。
