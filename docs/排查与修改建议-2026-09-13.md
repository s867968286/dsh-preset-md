## 1. 🔴 必修

### A. 未按 `source.kind === 'user'` 过滤

**现象**：转写里混入官方运行时快照、压缩 checkpoint、其他插件的注入消息；触发阈值虚高。

**根因**：`user/message` 这个事件类型**不区分来源**——真人发言、官方上下文快照、插件通知
全部以它落盘，要靠 `source.kind` 区分。

**证据**：

```js
// src/review.mjs:44-46 —— 所有 user/message 当真人发言
if (event?.type === 'user/message') {
  const text = textOf(event.data?.content)
  if (text) lines.push(`用户：${text}`)
}

// src/preset.js:140 —— 所有 user/message 计入触发阈值
if (event?.type === 'user/message') total += textLength(event.data?.content)
```

全 `src/` 下 `grep 'source.kind'` **零命中**。

**为什么是真问题**（三重后果）：

1. **自我喂养**：快照里含记忆条目的标题与描述，被当用户发言喂给回顾模型 → 可能据此再写一条重复记忆
2. **阈值虚高**：注入文本计入 `grown`，可能在**没有任何真人输入**时越过 `reviewChars` 触发回顾
3. **日志污染**：`用户：…` 段落里混入官方快照与压缩摘要

**缓解因素（不构成免修）**：`runReview` 有 `minChars = 80` 最低门槛（`src/review.mjs:304`），
且模板写了提示词层防御（`templates/SYSTEM.md.tpl:9-10`「忽略不属于你的全局记忆快照」）——
**但那是提示，不是机制**。

**改法**：

```js
// 新增一个判定函数（可放 src/review.mjs 并导出，供 preset.js 复用）
export function isHumanMessage(event) {
  return event?.type === 'user/message' && event.data?.source?.kind === 'user'
}
```

```js
// src/review.mjs:44 改为
if (isHumanMessage(event)) { ... }

// src/preset.js:140 改为
if (isHumanMessage(event)) total += textLength(event.data?.content)
```

**用严格匹配**（`=== 'user'`）而非宽容放行：官方契约里 `Message.source` 是**必填**字段，
严格匹配不会漏；宽容放行反而会漏掉未来新增的插件来源。

**必须同时补回归测试**（见 §5 测试建议 T1）。现有的
`test/review.test.mjs:125-134` 只放了裸 `user/message`（**无 `source` 字段**），测不出这个问题。

### B. 水位在执行前推进 → 失败静默丢内容

**现象**：回顾失败时不重试、水位已推进；长会话里该轮内容滚出尾部窗口后**静默丢失**，
日志与界面都看不出发生过。

**根因**：`markChars` 在 `schedule()` 的**同步阶段**就推进，早于 LLM 调用。

**证据**：

```js
// src/preset.js:379-382 —— 赋值发生在 void(async()=>{...})() 之前
state.running = true
state.runningSince = now
state.turns = 0
state.markChars = transcriptCharsOf(agent)     // ← 执行前就推进

void (async () => { ... })()
```

失败分支（`src/preset.js:430-433`）只打日志 + 通知，**不回滚水位**：

```js
} catch (error) {
  logger.warn?.(`[preset-md] 自动记忆失败：${detail}`)
  notify(agent, key, `自动记忆已满足触发条件（${reason}），但执行失败：${detail}`)
}
```

**同类先例**：`dsh-auto-memory` 犯同一个错（冷却/额度在调用子代理前扣减），
导致它的重试队列在默认配置下**永远没有预算可用**（子代理实测两次真实定时器 tick 都没能产生第二次调用）。

**改法**：把水位推进移到**成功之后**。

```js
const schedule = (agent, key, reason, force = false) => {
  const state = stateOf(key)
  // ... 前置守卫不变 ...

  const now = Date.now()
  if (!force && now - state.lastAt < REVIEW_DEBOUNCE_MS) return
  state.lastAt = now
  state.running = true
  state.runningSince = now
  const marksAt = transcriptCharsOf(agent)   // 先算出来，但**不写回 state**

  void (async () => {
    try {
      // ... 现有逻辑 ...
      // 只在成功路径推进（含「正常跳过」与「解析失败」之外的完成态）
      state.turns = 0
      state.markChars = marksAt
    } catch (error) {
      // 失败：不推进水位，下一轮自然重试同一段
      // （注意：turns 也不清零，让它继续累积）
    } finally {
      // ... 现有 finally ...
    }
  })()
}
```

**注意**：`turns` 同理 —— 失败时不应清零，否则「轮数阈值」也被消耗掉。
但要防止无限重试：可加一个 `attempts` 计数，连续失败 N 次后强制推进（参考
`dsh-memory-md` 的 `MAX_SUMMARY_ATTEMPTS = 3` 做法，避免一段坏内容让水位永久卡死）。

**好消息**：因为转写是「整会话尾部窗口」，失败那轮内容**通常**仍在窗口内会被下次带上。
所以这条的实际影响是**长会话**才致命 —— 但正因为隐蔽，更该修。

## 2. 🟡 建议补

### C. `{{}}` 安全是「协议依赖」，没有测试保护

**现状**：**当前是正确的**。section 文本只有 `{{preset_md}}`（`src/core.js:382`），
6 个 MD 正文全在**变量右值**里（`src/core.js:421-433`），而官方
`interpolate()` **不二次扫描替换值**（`dsh-system-prompt/lib/index.js:104-113`，
注释原文 *"substituted values are not scanned again"*）。

**实测验证**（逐字跑官方算法）：

| 正文内容 | 结果 |
|---|---|
| 已知占位符 `{{cwd}}` | ✅ 正常替换 |
| 未识别 `{{foo}}` | ✅ 原样保留 |
| wiki 模板 `{{hl\|}}` | ✅ 安全 |
| 中文 `{{挖空}}` | ✅ 安全 |
| 三层 `{{{triple}}}` | ✅ 安全 |
| 无闭合 `{{` | ✅ 安全 |

**风险**：这是**协议依赖型安全**，不是**防御型安全**。任何把正文挪回 `section.text` 的重构，
风险立刻回来 —— 而**测试测不出**（现有 `test/core.test.mjs:215` 只测了
`substitutePlaceholders` 保留 `{{unknown}}`，没走官方 `interpolate`）。

**对比**：Hanako 与 claw-suite 都栽在这里 —— 实测把用户文本直拼 section 后，
含 `{{我的暗号}}` 的档案会让**每次新会话都炸整轮**。

**改法**：补一条**端到端**测试，锁住当前契约（见 §5 T2）。

### D. 未在压缩前 flush 记忆

**现象**：上下文压缩（compaction）会把老对话摘要掉。若某段工作还没被回顾总结，
压缩后就**再也没有机会**总结它 —— 内容已不在事件窗口内。

**先例**：`dsh-claw-suite` 专门做了这件事（`dsh-agent-memory/host.js:463-475`）：

```js
const stopFlush = ctx.on && ctx.on('session/event', (session, event) => {
  if (!event || event.type !== 'compaction/start') return
  // ... force:true 绕过长度检查，withTimeout(12000) 兜底
  return withTimeout(reviewSession(agent, session, cwd, settings, {
    force: true,
    mark: 'compaction:' + (event.data?.compactionId || event.seq || ''),
  }), REVIEW_TIMEOUT_MS).catch(() => {})
})
```

**改法**：在 `src/preset.js` 加一个 `session/event` 监听，只在 `compaction/start` 时
`schedule(agent, key, 'compaction', true)`，外包 `withTimeout` 兜底。

**注意**：`agent/disposed` 路径已有 force 触发，这条是**补压缩这个额外场景**。

`context`（沙箱策略等）也未被清空。

## 7. 官方机制速查（改代码前对照）

| 机制 | 位置 | 要点 |
|---|---|---|
| `interpolate()` 严格校验 | `dsh-system-prompt/lib/index.js:151-175` | 未知变量/非法名字**抛错**；替换值**不重扫** |
| `complete` 替换全部 section | `dsh-system-prompt/lib/index.js:352-357` | 只能有一个；`dsh-persona` 也有此配置 |
| 空 text 的 section 被过滤 | `dsh-system-prompt/lib/index.js:112` | 变量返回空串 → 段自动消失 |
| `section`/`context` 独立排序空间 | `dsh-system-prompt/lib/index.js:331`、`:344` | 同一 order 数值在两边不冲突 |
| `turn-stopping` 在 error/abort **不派发** | `dsh-agent-loop/lib/index.js:966-991` | 派发点在 `try` 块内；error 走 `catch` 直接抛 |
| `assistant/message` 结构 | `dsh-session/lib/types/types.d.ts:309-317` | 正文在 `data.message.content` |
| `user/message` 结构 | `dsh-session` 的 `deriveEventMessage` | 正文在 **`data.content`**（与 assistant 不对称） |
| `agent.inject` 语义 | `dsh-agent-loop/lib/index.js:795` | `next-step` 且 `wakeup=false` —— 对已销毁 agent 注入**无效** |

## 8. 已知的边界与不确定性

诚实标注，避免把结论当绝对：

1. **官方包版本**：本机为 `0.1.5-rc.2`，插件声明 `^0.1.0-rc.6`。
   涉及 `session.events` 之类 API 的结论**限定于当前安装版本**。
2. **`agent/disposed` 的失败提示可见性**：`agent.inject` 对已销毁 agent 注入无效，
   而 README:128 承诺「会话结束必触发」—— 这条路径上的失败提示**用户看不到**。
   若要让失败真正可见，需改用别的通道（如写入日志文件 + 界面展示）。
   附带：官方 `agent/disposed` 由 `emitDisposed` 在 `entry.announced` 时才发（`dsh-agent/lib/index.js:512-517`），
   若不发则 force 触发也不会执行。
3. **`memory/` 天文件无上限**：`src/memory-store.mjs` 全文件无相关常量。
   检索是 O(文件数 × 行数 × 子串)，`days` 调大后线性劣化。
   按当前设计原则（不设硬限、超了人工优化）这是**有意的**，但值得知道。
4. **`state` Map 泄漏面很小**：只在 `agent/disposed` 后延迟 5 分钟清理（`src/preset.js:468`）；
   若某会话有 `turn-stopping` 却从不 `disposed`（如插件卸载路径），条目会长期留存。
